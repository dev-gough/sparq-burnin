# Mobile layout review

The mobile shell applies below 768px. The desktop navigation rail and page layouts keep their existing dimensions. Phone navigation uses a left sidebar drawer with route links, account controls, theme and timezone preferences. Navigation and downloads share `SidebarDrawer`; Export opens a drawer with CSV and ZIP actions. The mobile header puts navigation and downloads on the left and the SPARQ logo on the right. The redundant settings cog has been removed; result mode and date sync remain in the dashboard table controls. On phones, dashboard actions share the top navigation bar and the date row pulls into the fixed bar as the dashboard scrolls, leaving the selected pill visible. The selected radio remains the painted pill throughout the transition, with an invisible header tap target, avoiding an end-of-animation handoff. The folded pill is at least 84px wide with larger text. Tapping the pill expands the row in place; returning to the top expands it automatically. The content keeps its original position throughout. All five date selectors have matching 44px heights and equal widths. Analytics headers give period controls their own row. The mobile navigation sidebar fills the available height and uses a single column at 184–208px wide, roughly half a phone viewport. BurnIn and its description share a compact header row. Clock and theme controls are borderless icons; an account circle and sign-in/out icon sit at the bottom left. Link heights adapt to short viewports, keeping all actions visible without scrolling. Download drawers retain their wider layout. A 160ms transform animation opens it from the left; reduced motion disables it. The all-time comparison note spans the full mobile grid in one line. The main table keeps serial search full width, followed by one row of result, category, firmware, optional station and More dropdowns. More holds the existing mode and date-link switches, and opens a replacement date picker for independent table dates when unlinked. Dashboard table and cause menus share one active panel; replacements wait for the previous panel to finish closing, with focus preserved. Failure causes use a single mobile row of split group buttons: the main button toggles the whole group, while its arrow offers all causes in the group or individual causes. A small coverage menu retains untagged review, tagged filtering, and clearing. Long group lists swipe horizontally without a visible scrollbar. Active filter chips retain the selected values. Tests, todo items and contributors use mobile cards; test charts and annotations stack, with an annotations shortcut. Station controls wrap, chart labels thin out, and dialogs and popovers fit short viewports.

## Repeat the screenshot checks

Start a local development server with authentication bypassed:

```sh
SKIP_AUTH=true npm run dev -- --hostname 127.0.0.1 --port 3100
```

In another terminal:

```sh
npm run test:mobile
```

The script uses system Chromium if present; otherwise install Playwright's browser with `npx playwright install chromium`. Set `CHROMIUM_PATH` to choose a different Chromium executable. `BASE_URL`, `OUTPUT_DIR` and comma-separated `WIDTHS` can override the local URL, screenshot destination and viewport matrix. It only accepts loopback URLs and intercepts API calls with representative fixtures, including station administration; it does not modify a database.

The default matrix covers all 11 page routes at 320, 390, 768 and 1440 pixels. It checks page overflow, chart resizing and browser runtime errors, then exercises navigation, route dismissal, Escape, date selection controls, download drawers, CSV/ZIP downloads, custom-range export restrictions, rolling chart controls, test fullscreen, annotations, status history, landscape sizing, theme changes and resizing with navigation open. Additional checks at 320, 384 and 412px verify that dashboard chrome uses at most 120px, dates fold into the header, selectors match, and the administrator menu fits within a 700px-high viewport. Drawer checks additionally cover 320×480, 320×568, 360×640, 384×824, 412×915, 568×320, 667×375 and 740×360, plus resizing while open. They verify every action stays on-screen without a scrollbar, single-column navigation, header alignment, footer account placement, borderless preference icons, timezone selection, animation duration and reduced motion. Table-filter checks at 320, 390 and 412px include the optional station, every dropdown selection, mode and date-link switches, independent dates, serial search, exclusive menu transitions, rapid switches, and reduced motion. Failure-cause checks cover the single row, whole-group toggles, individual causes, coverage actions, and group reselection. Date-fold checks verify the larger pill stays visible and aligned after the transition and cover each preset, Custom, expansion without scroll jumps, return to top, rapid reversals, keyboard focus, reduced motion and resizing back to desktop. Screenshots include each route, scrolling sections, overlays, expanded and folded dates, and intermediate animation frames. Output defaults to `/tmp/burnin-mobile-review`, including `layout-report.json` with geometry for desktop comparisons.

The initial review also compared the visible heading, card and chart geometry at 1440px against the unchanged checkout. All 11 routes matched. Screenshots use fixture data because the local database did not return usable data for several endpoints; production data and iOS Safari were not available to this automated check.

For loading transitions, run `BASE_URL=http://localhost:3100 SKELETON_REVIEW=1 npm run test:mobile`. This holds the contributors, failure analytics, and dashboard API responses, captures loading and loaded screenshots at 320, 412, and 1440px, and checks that the contributors activity and analytics trend charts keep the same vertical position after loading. Contributor counts and cause rankings remain variable in height because their contents are unknown before the response arrives.
